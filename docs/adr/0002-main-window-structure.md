# ADR 0002: 主窗口结构 - 功能域独立架构

## Status
Accepted (2026-06-13), amended by ADR 0008

The feature-domain settings structure remains accepted. ADR 0008 supersedes this ADR's History and Favorites navigation placement and the rejection of a unified Library surface.

**原型验证**：已通过 UI 原型验证，确认 6 标签页 + 二级导航结构可行。

## Context

SnapLingo 整合了截图、OCR、翻译三大功能，需要设计一个主窗口（Settings Window）来组织配置界面。研究了两个参考应用的架构：

- **Snipaste**：纯托盘应用，无主窗口，设置窗口是模态对话框（标签页式）
- **Bob**：托盘 + 偏好设置窗口，使用"插件架构"模式，服务配置集中在"插件"标签页

SnapLingo 的需求：
1. 需要传统主窗口（非纯托盘应用）
2. 托盘常驻（快捷键继续工作）
3. 三大功能（截图、OCR、翻译）的设置需要分开清晰
4. Provider 配置需要统一管理

设计挑战：
- 如何平衡功能独立性和配置集中性？
- 历史记录和收藏夹应该统一还是分散？
- 快捷键配置应该按功能域还是集中在一个"快捷键"页面？

## Decision

采用**功能域独立架构**：主窗口包含 6 个一级标签页，每个功能域（截图/翻译/OCR）拥有完整的二级导航，包含该域的快捷键、设置、历史、收藏。

### 主窗口结构

```
主窗口（左侧导航栏）：
├─ 📸 截图
│   ├─ 快捷键（截屏、贴图相关）
│   ├─ 保存设置
│   ├─ 编辑器
│   └─ 收藏夹
│
├─ 🌐 翻译
│   ├─ 快捷键（划词、截图翻译、输入翻译）
│   ├─ 翻译设置
│   ├─ 历史记录
│   └─ 收藏夹
│
├─ 🔍 OCR
│   ├─ 快捷键（截图OCR、静默OCR、访问选图OCR）
│   ├─ OCR 设置
│   ├─ 历史记录
│   └─ 收藏夹
│
├─ 🔌 服务（顶部标签切换）
│   ├─ [OCR 服务]
│   ├─ [翻译服务]
│   └─ [语音合成]
│
├─ ⚙️ 通用
│   ├─ 界面
│   ├─ 应用快捷键
│   └─ 关于
│
└─ 🔧 高级
    ├─ 网络
    ├─ 日志
    └─ 数据管理
```

### 关键原则

1. **功能域完整性**：每个功能域（截图/翻译/OCR）包含该域的所有配置，用户无需跨标签页寻找设置
2. **服务集中管理**：所有 Provider（OCR/翻译/TTS）配置集中在"服务"标签页，采用 Bob 的"插件架构"模式
3. **历史记录分离**：翻译和 OCR 各自维护历史记录，截图无历史（用户通过文件系统或收藏夹管理）
4. **快捷键就近配置**：快捷键配置在对应功能域内，而非集中在"通用"设置

### 快捷键分配

基于 Bob 的快捷键模式（⌥⇧⌘ + 字母），避免与系统快捷键冲突：

**翻译相关**：
- 划词翻译：⌥⇧⌘D
- 截图翻译：⌥⇧⌘S（截图 → OCR → 自动翻译）
- 输入翻译：⌥⇧⌘A
- 显示翻译窗口：⌥⇧⌘

**OCR 相关**：
- 截图 OCR：⌥⇧⌘S（与截图翻译共享触发方式，但结果不同）
- 静默截图 OCR：默认未设置
- 访问选图 OCR：默认未设置
- 显示 OCR 窗口：默认未设置

**截图相关**（继承 Snipaste 风格）：
- 截屏：F1
- 贴图：F3
- 其他贴图管理快捷键

## Consequences

### 优点

1. **用户心智模型清晰**：一个功能域的所有配置在一个地方，符合"信息香味"原则
2. **扩展性强**：未来添加新功能（如"朗读"），可以新增一个完整的标签页
3. **符合参考案例**：Bob 的"插件架构"验证了服务集中管理的有效性
4. **减少标签数量**：6 个一级标签（研究报告建议 5-8 个）

### 缺点

1. **配置分散**：快捷键配置分散在三个 tab，对于想统一查看所有快捷键的用户不便
   - **缓解**：可在"通用 → 应用快捷键"提供"查看所有快捷键"的汇总视图
2. **二级导航复杂度**：翻译和 OCR tab 有 4 个二级导航项，需要良好的视觉设计
   - **缓解**：使用左侧二级导航栏（已在当前代码中实现）
3. **"截图"tab 内容较少**：只有配置，没有历史记录
   - **可接受**：截图是"一次性操作"，历史通过文件系统管理更合理

### 替代方案（已否决）

**方案 A：Bob 风格 - 插件架构**
```
主窗口：Dashboard / 服务 / 历史 / 设置
```
- 缺点：功能域不清晰，所有设置混在"设置"tab

**方案 B：扁平式 - 7 个一级标签**
```
主窗口：截图 / OCR / 翻译 / 服务 / 历史 / 通用 / 高级
```
- 缺点：标签太多（7个），历史记录统一管理会混乱（截图/OCR/翻译混在一起）

**方案 C：两级嵌套 - OCR/翻译内部二级导航管理 Provider**
```
翻译 tab → 左侧导航：Google / DeepL / 百度...
```
- 缺点：Provider 配置分散，用户想切换 OCR 引擎时需要从"OCR tab"进入，切换翻译服务时需要从"翻译 tab"进入，不如统一在"服务"tab 方便

## Prototype Validation (2026-06-13)

### 验证方法
构建了完整的交互式 UI 原型（`designs/prototypes/App.PROTOTYPE_UI.tsx`），包含：
- 6 个主标签页的完整导航
- 截图/翻译/OCR 的二级导航和快捷键设置页面
- 服务 tab 的 Provider 卡片展示
- 快捷键显示组件（Bob 风格）

### 验证结果

**通过验证**：
- ✅ 6 个主标签页数量合理，不会让用户感到过载
- ✅ 左侧主导航（90px）+ 二级导航（224px）布局清晰
- ✅ 快捷键设置交互符合现代应用习惯（点击录制 + 全局操作按钮）
- ✅ 图标识别度良好（相机/地球仪/扫描框/堆叠卡片/滑动开关/放射控制）
- ✅ 服务 tab 的顶部标签切换与其他 tab 的二级导航区分明确

**调整点**：
- 快捷键显示样式优化为 Bob 风格（修饰键始终显示，激活时变色）
- 快捷键操作简化（去掉每行的"重置"和"检测"按钮，改为全局按钮）
- 图标经过多次迭代，最终选择简洁识别度高的版本
