# SnapLingo - 产品需求文档

## 问题陈述

用户经常需要从图片中提取文字，或者翻译外语内容。现有的解决方案需要使用多个工具：一个截图工具、一个 OCR 工具、再加上一个翻译工具。这种碎片化的工作流程既慢又打断专注力。

现有工具如 Bob（仅 macOS）展示了集成 OCR 和翻译的价值，但缺乏全面的截图编辑功能和跨平台支持。用户需要一个统一的工具，结合 Snipaste 级别的截图编辑、强大的 OCR 和多供应商翻译能力，并且支持所有主流操作系统。

## 解决方案

SnapLingo 是一款跨平台桌面应用，将截图捕获、OCR 和翻译统一到单一的无缝工作流中。用户可以：

1. 使用专业级标注工具捕获和编辑截图
2. 即时从图片中提取文字并使用多个翻译引擎同时翻译
3. 通过键盘快捷键快速翻译任何应用中选中的文字
4. 在统一界面中对比不同供应商的翻译质量（DeepL、OpenAI、Google 等）
5. 通过使用本地 OCR 引擎或配置自己的 API Key 完全控制数据

应用以系统托盘工具形式运行，支持全局快捷键，无需窗口管理。所有翻译服务都采用自带 API Key 模式，确保隐私和成本控制。

## 核心功能

### 五种捕获模式

1. **截图模式（Screenshot Mode）** - 快捷键 F1
   - 框选、窗口识别、全屏捕获
   - 完整编辑工具集：矩形、椭圆、箭头、折线、画笔、马克笔、文字、马赛克、高斯模糊、橡皮擦
   - 保存/复制/贴图功能
   - 贴图：置顶浮动窗口，可拖动缩放，支持多个贴图

2. **OCR 模式（OCR Mode）** - 快捷键 Option/Alt+A
   - 框选后自动 OCR 识别文字
   - 显示识别结果，可手动点击"翻译"按钮

3. **OCR+翻译模式（OCR + Translation Mode）** - 快捷键 Option/Alt+S
   - 框选后自动 OCR 并翻译
   - OCR 完成后立即显示文本，翻译在后台执行

4. **划词翻译模式（Selection Translation Mode）** - 快捷键 Option/Alt+D
   - 选中文字后按快捷键
   - 自动复制选中内容并翻译
   - 注意：快捷键仅在有文本被选中时生效

5. **输入翻译模式（Input Translation Mode）** - 快捷键 Option/Alt+W
   - 弹出翻译窗口
   - 用户直接输入文字翻译

### Provider 系统

**OCR Provider（单选激活）**：
- 本地：Tesseract、PaddleOCR
- 云端：百度 OCR、腾讯云 OCR、Google Cloud Vision、Azure Computer Vision

**Translation Provider（多选激活）**：
- 免费：Google Translate
- 付费：DeepL、OpenAI、百度翻译、有道翻译、腾讯翻译君、Azure Translator
- 自定义：支持 OpenAI/Claude/Gemini 兼容 API 格式

**重点**：
- OCR 只能激活一个（尝试激活第二个会警告）
- 翻译可以同时激活多个，结果并排显示对比
- 应用本身不提供付费服务，用户自己配置 API Key

### 统一结果窗口（Result Window）

所有翻译场景共用同一个窗口：

**窗口结构**：
- 顶部可编辑文本区域（原文）
  - 根据场景不同：OCR 结果、剪贴板内容、或空白输入框
  - 右侧"朗读"按钮（系统 TTS）
- 语言选择控件
  - 源语言下拉框（支持"自动检测"）
  - 目标语言下拉框
  - 交换按钮
- "翻译"按钮
- 翻译结果卡片列表（垂直布局）
  - 每个激活的 Provider 一个卡片
  - 卡片头部显示 Provider 名称和图标
  - 可折叠/展开
  - 每个卡片有"复制"和"朗读"按钮

**窗口行为**：
- 位置：默认屏幕中央，记住最后拖动位置
- 关闭方式：
  - 按 ESC 键
  - 点击窗口外（默认）
  - 可勾选"保持打开"，禁用点击外部关闭
- 持久性：窗口保持打开，允许编辑文本后重新翻译

**语言智能检测**：
- 自动检测源语言（使用本地库）
- 智能目标语言：
  - 检测到中文 → 翻译成英文
  - 检测到非中文 → 翻译成中文
- 用户可手动调整后重新翻译

### 截图编辑工具

完整的 Snipaste 级别工具集：

- **几何图形**：矩形、椭圆、箭头、折线（按住 Shift 约束）
- **绘制**：画笔（自由绘制）、马克笔（半透明高亮）
- **效果**：马赛克、高斯模糊、橡皮擦
- **文本标注**：可调字体、大小、颜色
- **操作**：撤销/重做、颜色选择器、粗细调整、填充/边框切换

**双层架构**：
- 原始截图层（用于 OCR，不含标注）
- 标注层（用于显示和保存）
- 编辑窗口中点击"OCR"按钮，识别的是原始截图

### 系统托盘菜单

应用常驻托盘，无主窗口，通过托盘菜单交互：

- **截图**（子菜单）
  - 普通截图
  - OCR 截图
  - OCR + 翻译
- **快捷翻译**：打开输入翻译窗口
- **历史记录**：查看历史操作
- **设置**：打开设置窗口
- **关于**：版本信息
- **退出**

### 设置界面

左侧分类导航 + 右侧配置项布局：

1. **通用设置**
   - 开机自启
   - 界面语言
   - 主题（浅色/深色/跟随系统）

2. **截图设置**
   - 默认保存路径
   - 图片格式（PNG/JPG/WebP）
   - 图片质量
   - 默认工具颜色和粗细

3. **OCR 设置**
   - OCR Provider 选择（单选）
   - API Key 配置

4. **翻译设置**
   - Translation Provider 选择（多选）
   - API Key 配置
   - 自定义 Provider 管理
   - 默认目标语言

5. **快捷键设置**
   - 自定义所有快捷键
   - 冲突检测

6. **历史记录设置**
   - 选择记录哪些内容
   - 自动清理配置（天数/条数）

7. **高级设置**
   - 网络代理
   - 日志级别
   - 清除所有数据

### 历史记录

**记录内容**（可配置）：
- 截图保存操作
- OCR 识别结果
- 翻译结果

**记录结构**：
- 每次操作一条记录
- 包含：时间戳、操作类型、相关数据（图片缩略图、文本、翻译等）

**自动清理**（可配置）：
- 超过 N 天的记录（默认 30 天）
- 记录总数超过 N 条（默认 1000 条）

### 配置存储

**Provider 配置与凭据**：
- Endpoint、Base URL、API Key 与其他应用设置统一保存在本机 SQLite（`snaplingo.db`）
- 当前小范围测试版本接受 API Key 在 SQLite 中明文保存
- 配置不随应用卸载删除

## 技术架构

### 技术栈

- **框架**：Tauri 2.0（Rust + Web）
- **前端**：React + TypeScript + TailwindCSS
- **后端**：Rust

### 职责分层

**前端（React）**：
- 所有 UI 渲染（截图编辑器、结果窗口、设置界面）
- Canvas 绘图（截图编辑工具）
- 用户交互处理

**后端（Rust）**：
- 系统调用（截图、全局快捷键、剪贴板）
- 图片处理（合成标注层和原图、保存、格式转换）
- Provider 调用（HTTP 请求到 OCR/翻译 API）
- 语言检测
- 配置管理
- 历史记录存储
- TTS 调用（系统 TTS API）

## MVP 范围（P0 + P1）

### P0 - 必须有

1. Screenshot Mode - 完整编辑工具
2. OCR + Translation Mode - 至少一个 OCR 和一个翻译 Provider
3. Selection Translation Mode
4. Result Window - 统一结果窗口
5. 基础设置

### P1 - 第一版包含

1. Input Translation Mode
2. 贴图功能
3. 历史记录
4. 多 Provider 支持
5. 自定义 Translation Provider
6. 完整设置界面

**预计时间**：6-8 周

### P2 - 延后

1. 主题切换
2. 网络代理
3. TTS 朗读
4. 更多内置 Provider
5. 界面多语言

## 不在范围内

### 永久排除

1. 内置付费/订阅系统 - 永远 BYOK（自带 API Key）
2. 用户账号或认证 - 纯本地应用
3. 社交功能（分享到 Twitter 等）
4. AI 模型训练或微调
5. 文档编辑（非截图类，如 PDF 编辑器）
6. 多页 OCR 扫描工作流

## 性能目标

- 冷启动（应用启动到托盘图标显示）：< 2 秒
- 截图捕获到编辑器显示：< 100ms
- OCR（Tesseract，中等图片）：< 3 秒
- 翻译 API 调用：< 2 秒（取决于网络）
- 内存占用（空闲）：< 150MB
- 内存占用（5 个贴图）：< 300MB

## 隐私和安全

- 默认无遥测或分析
- 可选崩溃报告（明确选择加入）
- 所有 API Key 在系统凭据存储中加密
- 无用户配置 Provider 时，无网络请求
- 本地优先：OCR 和翻译仅在用户触发时执行
- 剪贴板访问仅在划词翻译模式（不是被动监控）

## 已知限制

1. **Wayland 截图**：取决于混成器支持（部分混成器出于安全阻止截图）
2. **Linux 全局快捷键**：需要 X11 或混成器协议支持
3. **OCR 准确率**：Tesseract/PaddleOCR 不错但不完美，关键场景可能需要云端
4. **翻译上下文**：单文本翻译缺少上下文；LLM Provider（OpenAI/Claude）对段落效果更好
5. **系统要求**：
   - Windows 10+（Tauri 2.0 不支持 Win 7/8）
   - macOS 11+（旧版本缺少必要 API）

## 风险和缓解

| 风险 | 缓解措施 |
|------|---------|
| Provider API 速率限制太容易触发 | 清晰的 UI 反馈速率限制状态，建议本地 Provider 作为备选 |
| 快捷键冲突导致应用无法工作 | 强大的冲突检测，建议替代快捷键，托盘菜单作为后备 |
| OCR 准确率差让用户失望 | 内置多个 OCR 引擎，清晰指导何时使用云端 vs 本地 |
| Tauri 跨平台问题（如 Wayland 支持） | 早期在所有平台测试，文档记录已知限制，优雅降级 |
| 翻译 Provider API 变化导致集成失效 | 单独版本化 Provider 实现，基于 Schema 的 API 定义，社区可快速贡献修复 |

## 开放问题（待实现时决定）

1. 历史缩略图应该全分辨率还是压缩？（权衡：细节 vs 空间）
2. 贴图是否应该保存到磁盘以便崩溃后恢复？（P0 说否，但用户可能期待）
3. 是否应该限制 Provider API 调用速率以防用户意外消耗额度？（默认：否，尊重用户配置的限制）
4. Result Window 是否应该支持富文本格式（保留 LLM 响应的粗体/斜体）？（P0：纯文本，延后）
5. 划词翻译是否应该自动检测代码块并相应格式化？（P0：当作纯文本，延后）
