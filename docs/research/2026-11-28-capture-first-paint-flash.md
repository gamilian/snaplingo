# 选区弹出时的整屏闪烁

安装 v0.1.30 后，用户反馈快捷键弹出选区时整屏明暗或内容闪一下，也询问是否因为动画缺失或过渡生硬。

## 已验证原因

原生截图窗口明确禁用 AppKit 动画；选区根节点没有淡入/透明度过渡。已有的 110 ms 动画只作用于选区完成后的编辑工具栏。

专用入口 `capture.html` 使用 `html, body, #root { background: transparent; }`。生产构建把共享 CSS 放到这段内联样式之后；共享 `body { background: rgb(var(--canvas)); }` 与内联 body 规则具有相同优先级，后加载的共享规则胜出。图片未完成解码时，窗口因此显示主题底色，而不是透出桌面。

生产样式顺序回放结果：

| 主题 | 修改前 body 背景 | 修改后 |
| --- | --- | --- |
| 浅色 | rgb(248 249 252) | transparent |
| 深色 | rgb(32 39 49) | transparent |

用户本机 v0.1.30 的 2026-11-27 23:43:02 记录中，前端 `revealed` 为 181 ms，`images_ready` 为 214 ms，存在约 33 ms 的底图未就绪可见窗口。这条日志证明该间隙实际出现过；并未通过屏幕录像确认每次闪烁都只有这一种原因。

## 修复与验证

截图入口按 `html[data-window="capture"]` 限定透明样式，提高选择器优先级。选区仍可提前交互，普通设置窗口继续使用主题背景。

按后续用户要求增加 100 ms 淡入：原生窗口实际显示后，蒙层才开始淡入；底图保持隐藏，所有图片解码后再淡入，避免部分加载及旧帧直接切入。再次截图时立即清掉旧层的可见状态，不播放退场动画。过渡只影响视觉层，鼠标命中层持续可用；系统“减少动态效果”启用时禁用过渡。

`npm test -- src/styles/captureCanvas.test.ts` 在浅色、深色主题下均先失败，再通过；测试按生产顺序加载入口内联 CSS 和共享 CSS，并检查 html、body、root。另用真实 `dist/capture.html` 和生成 CSS 做差分回放，得到表中结果。选区生命周期、首次绘制、样式相关测试通过；加入过渡后，完整前端测试为 1066 项通过、1 项已有测试跳过，生产构建通过。过渡测试同时覆盖原生窗口尚未显示、图片尚未解码、旧会话异步返回和系统减少动态效果。

公开 v0.1.30 不包含此修复。本次另构建本地修复版供验证。背景问题修复后，动态桌面与冻结截图之间的内容差异、源应用失焦变化仍需实机观察；单元测试与 CSS 回放不等同于实机录像。
