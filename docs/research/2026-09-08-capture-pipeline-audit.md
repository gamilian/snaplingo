# 截图流程核查

目标：选区界面看到的内容与输出一致，保留可见的上层窗口，并支持多显示器坐标和像素拼接。此次检查基于工作区已有修改继续进行；菜单快捷键等无关改动保留。

## 确认并修复的问题

1. **选区与输出使用不同帧。** 原先后端提前冻结，但选区界面透明，显示实时桌面；工作区新增的松开鼠标后重新截图又可能捕获弹层关闭后的下层窗口。现已移除该刷新接口和调用，选区按各屏逻辑位置铺设缓存底图，预览、OCR、复制、保存、贴图继续从同一会话裁剪。
2. **显示时机早于底图就绪。** 原先只需会话元数据即可显示截图窗口。现改为加载全部缓存底图、等待所有图片解码、准备画布后才显示；同时修正了像素就绪标志在通知订阅者之后才更新的问题。
3. **Windows 混合 DPI 造成虚拟空隙或重叠。** 把每屏的物理原点分别除以各自缩放，会把实际相邻的显示器拆开。现以主屏比例建立截图坐标，窗口按物理尺寸定位，并调整 WebView 缩放；窗口候选、光标和控件查询使用同一坐标系。坐标函数移到可在当前平台执行的测试位置。
4. **分数缩放边缘裁剪越界。** 副屏处于正、负坐标时，浮点计算可能把图片边缘向外取整多出一像素。现在把逻辑相交区域换算后的源、目标矩形限制在实际图片和输出边界内。
5. **键盘和错误退出。** 展开真实 `KeyboardEvent` 不会复制原型上的按键和修饰键，导致截图快捷键失效。现显式读取这些属性，并让错误状态支持 Esc、缺少可选退出回调时正常隐藏窗口。另修复了会话加载失败时 `undefined` 与 `null` 的比较导致错误窗口无法显示的问题。
6. **旧会话清理可能销毁仍在使用的截图窗口。** macOS 原先在会话结束时直接销毁窗口，未检查是否还有正在显示的截图会话。现在先检查已有的显示会话计数，避免刷新或切换会话时被旧会话的清理误关。

## 验证证据

修复前运行过并失败的回归：

- `captureWorkspaceRuntime.test.ts`：底图未就绪仍显示；模拟前台窗口关闭后输出替换为下层窗口；未取得会话时错误窗口未显示。
- `CaptureWorkspaceLifecycle.test.ts`：完整 React 界面没有加载、显示各屏冻结图像；图片失败后无法通过真实 Esc 事件退出。
- `session_test.rs`：原刷新接口把前台颜色像素替换成下一帧的下层颜色。
- `render.rs`：125% 缩放、负坐标副屏的源矩形超过实际 PNG 边界。
- `screenshot/geometry.rs`：主屏 200%、右屏 100% 时，右屏起点错误地为 3840，而主屏逻辑右边缘为 1920。
- `capture_window/tauri.rs`：旧会话结束时，仍有活动显示会话却执行窗口销毁。

持续回归覆盖图片解码顺序、两屏分别铺图、同帧预览和输出、跨屏混合密度合成、负坐标、上下左右屏幕布局、125% / 150% / 175% / 200% / 225% 边缘裁剪、真实复制快捷键、错误退出和活动截图窗口的清理保护。

前端完整测试（120 个文件、870 项）和构建通过；macOS 后端 531 项单元测试、11 项集成测试、格式检查和全部 target 检查通过。具体命令：

```sh
npm test
npm run build
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo test --locked --manifest-path src-tauri/Cargo.toml
cargo check --locked --manifest-path src-tauri/Cargo.toml --all-targets
```

本机另运行了一个临时 AppKit / CoreGraphics 遮挡探针：显示蓝色背景窗口与红色前景窗口，调用生产截图路径使用的 `CGDisplayCreateImage` 保存图像，再隐藏红色窗口。旧图中心保持 `255,0,0,255`，新图中心为 `0,0,255,255`，验证了合成屏幕取图和冻结图像的稳定性。此探针验证原生取图机制，并非完整应用的端到端 UI 测试。

Windows 完整应用交叉检查因缺少 `x86_64-w64-mingw32-gcc` 无法构建 SQLite / WebP 的 C 依赖。随后用临时检查 crate 直接包含实际截图、坐标、窗口适配器源码及测试，以 `x86_64-pc-windows-gnu` 目标完成类型与编译检查；该结果不等同于 Windows 实机运行。

## 尚需真实硬件验收

当前环境只有一块 1920×1080 逻辑尺寸、2× 缩放的屏幕，且未开启独立显示器 Spaces。尚未实测双屏窗口显示、跨屏拖动、macOS 独立 Spaces / 全屏应用、Windows 实机 DPI 行为。

建议用两屏分别放置可辨认的前台弹层和背景窗口，覆盖左右、上下、错位排列和不同缩放，测试单屏及跨屏选区的预览、保存和 OCR。开启截图后关闭或移动原窗口，底图与输出应保持截图启动时的内容；调整选区也应始终使用同一帧。

修改位于源码；运行中的 `/Applications/SnapLingo.app` 未被替换。
