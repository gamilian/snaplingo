# Remaining seams for removing Tauri

This is a read-only audit of the native migration checkpoint. Both native platform entries exist; `tauri-shell` is still the app crate's default and the production release workflows still invoke the retained shell. Removing the dependency requires deleting that production path, not only making the feature nondefault.

## Parallel implementation slices

| Slice | Production files and action | Verification |
| --- | --- | --- |
| Entry and Cargo | Make the native entry the normal `snaplingo` executable; remove `tauri-shell`, optional `tauri`/`tauri-build`, old `main.rs`, and the Tauri `run` builder/command registry in `lib.rs`. Keep platform native modules and `RuntimeLifecycle`. Remove `tauri_build::build()` from `build.rs`; retain Windows native resources and the test composition generator until its consumers are migrated. | Native macOS and Windows build, `cargo tree --workspace` contains no `tauri`, `wry`, or `tao`; startup/resident/single-instance/quit/restart smoke. |
| Composition and obsolete adapters | Remove `composition/tauri_bridge.rs`, shell `commands/`, and Tauri host/bridge/runtime modules beneath Result, Pin, Capture, and scrolling. Their native replacements already implement portable ports. Delete only the Tauri branches of `dialogs.rs`, `shortcut.rs`, `window_position.rs`, and app-shell wrappers; retain pure geometry/backend functions that native code or tests use. The old `settings_window.rs` routing/geometry helpers can move to the native owner where still called. | App lib/infrastructure/architecture tests; audit architecture tests that currently name deleted shell files. |
| Settings webview removal | `infrastructure/system/settings_window` still contains the retained embedded WKWebView mount and hybrid bridges even though standalone native Settings now has all pages. Remove that production mount and WK-specific switching; keep native controls/canvas adapters referenced by the standalone owner. Remove WK fallback from self-selection after keeping AppKit `NSTextView` and drawn text-selection delivery. Persisted `SelfWebview` identifiers may remain for database compatibility. | Seven-page native settings smoke, capacity/notices tests, selected-text regression. |
| Runtime regression harness | Migrate `native_ui_workflows.rs` and `native_ui/{result_window,capture_window,editor_tools,carbon_hotkey}.rs` to the already existing `native_app_smoke`/AppKit loop, with injected capture/clipboard/providers and `DesktopEvents`. Their current Tauri `AppHandle`, `.manage`, `.state`, `.run_on_main_thread`, and event-listener plumbing is harness mechanics. Preserve capture/editor/Result/scrolling assertions and synthetic failure recovery. Delete only the obsolete frontend bridge/WK mounting/IPC assertions and native-vs-WebView benchmark arm after separate reference coverage exists. | Run equivalent real native Result, Capture, editor-tool, scrolling, pin, shortcut and lifecycle workflows without Tauri linked. |
| Production scripts and CI | Route ordinary build/release through `native-build.mjs` and native verification. Remove `run-tauri*.mjs`, Tauri config/capabilities, release-verification's CLI invocation and WebView2 bundle variants. Keep NSIS/MSI/portable smoke with its native bundle directory parameter. Change release workflows and update metadata URLs coherently; old package paths must not silently remain the release source. | Native macOS app/DMG signature+architecture checks; Windows MSVC PE+offline resources, NSIS/MSI/ZIP staging and ephemeral install/upgrade/uninstall smoke. |
| Reference frontend isolation | Keep React/Vite only as a development reference tool while geometry acceptance uses it. Move original HTML/TSX fixtures and needed sources under an explicit test/reference package, with no `@tauri-apps/api` startup. Remove `@tauri-apps/api` and `@tauri-apps/cli` from the normal application package and regenerate lockfiles/notices. References need only mocked ports/state and the original components/CSS. | `npm` reference/geometry tests, no production script starts Vite/React/Tauri; generated notices and lockfile consistency. |

## Tests that already do not need Tauri

`pinned_window_native`, `result_window_drag`, `scrolling_controls_native`, `scrolling_overlays_native`, `ui_thread_native`, `selected_text_native`, infrastructure integration tests, and shared core/storage/UI/render/accessibility tests are independent of the Tauri host. Keep them and remove obsolete imports/feature guards as necessary. Settings General/Features/Hotkeys native tests already use isolated composition and can keep their main-thread native harness. The `#[cfg(feature="tauri-shell")] mod commands` declarations in those tests can be deleted with the feature.

`architecture_dependency_test.rs` needs surgical updates: tests that open deleted `commands/*` or `capture_window/tauri.rs` paths should be replaced by equivalent native composition/port restrictions, or deleted where they assert a boundary that no longer exists. Keep core dependency direction, storage port, and composition-only platform selection checks.

## Acceptance still required

The macOS default Result/Capture/Pin adapters are preserved. Windows can compile and link its native path, but Windows UI/IME/mixed-DPI and installer execution acceptance must be run on Windows. Removing Tauri should not discard the existing injected-failure native workflows simply because `native_app_smoke` currently covers startup and Settings.
