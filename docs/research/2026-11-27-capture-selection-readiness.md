# 截图选区显示延迟：把底图解码移出交互等待链

用户目标：按快捷键后尽快看到选区并拖框，不能因为整屏底图尚未解码而等待。

## 本机运行证据

只读查询已安装 v0.1.28 的应用数据库，筛选最近 600 条 `[capture-perf]` 日志，包含 28 次显示记录：

| 阶段 | 中位耗时 | 范围 |
| --- | ---: | ---: |
| 后端创建会话至派发打开窗口 | 75.9 ms | 43.7–708.6 ms |
| 前端读取会话完成 | 8.5 ms | 2–106 ms |
| 前端原生几何准备完成 | 82.5 ms | 40–565 ms |
| 前端原底图解码及绘制准备完成 | 378 ms | 120–991 ms |
| 前端窗口显示完成 | 431 ms | 158–1159 ms |

前端计时从收到会话启动事件开始，各行是累计时间，不能相加。日志不是本轮修改后的实机测量。

最近一条记录（2026-11-27 21:53:52，Asia/Shanghai）中，后端为 63.2 ms，前端窗口几何准备在 65 ms 完成，但等到底图解码及绘制完成已经 311 ms，显示完成为 324 ms。该帧为 3840×2160，PNG 为 33,182,358 字节。另一条记录前端显示耗时 555 ms。

## 复现和改动

原 `prepareCaptureSurfaceForReveal` 在绘制选区之前等待所有 `HTMLImageElement.decode()`。用真实 React 选区组件挂起图片解码，即使原生窗口几何已就绪，200 ms 后仍没有调用窗口显示，用户无法开始拖框。

现在：

- 原生几何和选区蒙层准备完成即可显示，图片使用异步解码。
- 底图在独立生命周期中解码，不阻塞选区输入。
- 提前松开鼠标时保留选区及工具栏，等像素就绪再创建编辑画布，防止对未加载图片调用 `drawImage`。
- 后端已经冻结的同一帧继续用于最终输出，不在选区完成后重新抓屏。
- 保留图片加载失败提示；旧会话或已关闭会话的异步结果不会破坏当前会话。
- `selection_surface_ready` 和 `images_ready` 分别记录选区显示准备、底图解码完成，方便后续实机比较。

## 验证

复现命令：

```sh
npm test -- src/views/CaptureWorkspace/CaptureWorkspaceLifecycle.test.ts -t 'before image decoding'
```

修改前两项失败：图片解码挂起时，窗口显示调用次数为 0。修改后可在解码挂起期间显示窗口、拖框并确定选区，解码完成后补齐正确尺寸的预览；同时覆盖原生指针捕获被拒绝的回退路径。

临时差分回放使用提交版和修改版的实际显示准备函数，固定原生几何准备 20 ms、图片解码 400 ms、首次绘制 16 ms：显示准备从 416 ms 降到 36 ms。该结果说明消除了对图片解码的依赖，不代表真实快捷键端到端耗时。临时回放文件已删除。

完整前端测试与生产构建用于验证类型、视图调用契约、错误退出及冻结像素输出路径。

## 后续测量边界

本轮没有替换正在运行的应用，尚未取得新构建真实快捷键到选区显示的计时。首次创建或切换 Space 后重建 WebView 仍可能影响冷启动；现有原生日志峰值约 709 ms，需在新构建中单独比较。底图传输体积也仍有优化空间，但本轮首先移除了它对拖框的阻塞。
